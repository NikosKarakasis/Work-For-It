# 🏆 Devpost Submission Guide

> **Goal:** by the end of this guide your project is live on Devpost with everything judges need.
> ⏱ Time needed: ~20 minutes. Do this BEFORE the deadline rush — you can edit until the deadline.

---

## 📍 Step 1 — Get set up on Devpost (5 min)

1. Create an account at https://devpost.com (use the same email you registered with).
2. Open the hackathon page (link is shared by organizers) and click **"Join hackathon"**.
3. Every team member should join — Devpost lets you add teammates to a submission.

## 📍 Step 2 — Create your project

1. On the hackathon page click **"Submit a project"** (or My Projects → Create project).
2. Fill in each section using the template below — write it here first, then copy-paste.
3. Add your teammates under "Team".
4. Attach your links: **GitHub repo, demo video, slides**.
5. Click **Submit**. You can keep editing until the deadline.

---

# ✍️ Write-Up Template (fill this in, then copy to Devpost)

## Project Title

Short and memorable. Avoid generic names like "Hackathon Project".

Example: SmartAssist — AI Study Companion

## Elevator Pitch (1–2 sentences)

This appears in the project gallery — make it count.

Formula: **[Product] helps [who] do [what] by [how].**

Example: SmartAssist helps students automatically generate flashcards from lecture notes using AI, reducing study prep time.

## Inspiration

What problem made you build this? Who experiences it and why does it matter?

Example: Students spend too much time organizing study materials manually instead of focusing on learning.

## What it does

2–4 sentences. Focus on what a USER experiences, not the tech.

Example: Upload your lecture notes and SmartAssist instantly turns them into structured flashcards you can review, share, and export.

## How we built it

List your stack — Devpost also asks for "Built With" tags, so keep this handy:

- **Frontend:** e.g. React, Flutter, Streamlit
- **Backend:** e.g. Node.js, Python, Firebase
- **Database:** e.g. Firestore, PostgreSQL, MongoDB
- **APIs:** e.g. OpenAI, Google Cloud, Firebase Auth
- **Cloud / Deployment:** e.g. Google Cloud, Vercel, Render

## Challenges we ran into

Judges love honesty here — a real obstacle + how you handled it.

Example: Authentication integration and database synchronization.

## Accomplishments that we're proud of

Example: Successfully deployed a working AI-powered prototype in under 12 hours.

## What we learned

Example: Working with APIs in real-time applications and dividing work under time pressure.

## What's next

Example: Add mobile support, collaboration features, and export integrations.

# 🔗 Required Links Checklist

- [ ] **GitHub repository** (public! test in incognito)
- [ ] **Demo video** (YouTube link — unlisted is fine, private is NOT)
- [ ] **Slides** (set sharing to "anyone with the link can view")
- [ ] **Live demo URL** (if deployed)
- [ ] At least one **screenshot/image** uploaded to the gallery (projects with images get noticed)

---

# 💡 Tips for a Winning Devpost

- **Write for a tired judge.** They read dozens of these — short paragraphs, clear headers, no jargon.
- **Lead with the problem.** If the problem is believable, the solution is interesting.
- **Show, don't claim.** "Cut prep time from 2 hours to 5 minutes" beats "very efficient".
- **Don't leave sections empty.** A short honest sentence is better than nothing.

# ⚠️ Common Mistakes (instant point-losers)

- Private repo or broken video link 🔒
- Submitting at 11:59 — Devpost gets slow at deadline; submit a draft early, edit after
- Tagline that says nothing ("A cool app built at a hackathon")
- Forgetting to actually click **Submit** (a saved draft is not a submission!)
